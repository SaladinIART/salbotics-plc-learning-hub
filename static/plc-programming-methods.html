How To Write A Reliable PLC Program From Scratch

flowcharts first, Ladder first, then choose the right language for each job

Core idea

Reliable PLC programming is not typing rungs quickly. It is turning a real machine into a clear control story: modes, states, permissives, interlocks, alarms, outputs, recovery, tests, and documentation. Flowchart first, code second.

Important boundary

Normal PLC application code is not a substitute for a certified safety system. Emergency stops, guard locks, boiler trips, pressure protection, and high-risk motion require risk assessment, certified components, and qualified engineering review.

1. Reliable Program Method From Scratch

the order matters more than the software brand

Define safe state

For every output, write what it must do when stopped, faulted, E-stop active, comms lost, or mode changes.

Separate mode ownership

Manual, semi-auto, and auto should not fight for the same output. Make one command arbitration rung.

Name the truth

Use tags like CV101_DownstreamReady, Press_LubeOk, and Ster_CycleStep instead of mystery bits.

Build small blocks

One motor block, one valve block, one analog scaling block, one station sequence. Reuse instead of copying chaos.

Alarm as sentences

Alarm text should tell source, condition, and action: "CV101 blocked chute - inspect discharge before reset".

Test before site pressure

Create a test matrix for every state, interlock, permissive, fault, reset, and abnormal sensor condition.

2. Flowcharts Before Ladder

flowchart is the machine story; Ladder is only one expression of it

Flowchart rules

One state owns actionDo not let two states command the same output in different rungs.
Transitions are conditionsWrite exact conditions for moving from one state to another.
Fault path is explicitEvery running state must say what fault means and how reset works.
Timers live in statesStart timers only when the state is active, then use done bits as transitions.
Manual is separateManual commands share interlocks, but should not corrupt auto sequence steps.

LAD is not old-fashioned; it is one tool in a mixed toolkit

5. Hardware Processing Limits Shape The Programming Style

scan time, memory, watchdog, I/O update, and online troubleshooting matter

Scan time

Every extra rung, loop, communication call, and calculation adds work. Slow scans can miss short pulses or make control feel late.

Watchdog

Loops in ST must be bounded. A bad loop can exceed watchdog time and fault the controller.

Memory

Small PLCs may have limited program memory, retentive memory, timers, counters, and data tables.

Analog math

Floating point, filters, and PID blocks may be heavier on older CPUs. Use fixed-point or scaled integers when appropriate.

Communication load

HMI, SCADA, VFD networks, MQTT gateways, and remote I/O can affect update rates and diagnostics.

Maintainability

The fastest code is not always the best plant code. A readable rung during a 2 AM breakdown is worth a lot.

Case Study 1: Conveyor Train

best default: LAD for interlocks, SFC for sequence, ST only for counters/data

LAD version

CV01
AUTO_MODECV102_RUNNINGCHUTE_CLEAR/PULL_CORDCV101_RUN

Readable for maintenance: downstream, chute, pull-cord, run.

CV02
CV101_RUN/ZERO_SPEEDT_ZS 3sALM_ZERO_SPEED

Missing rotation after command becomes a fault.

ST version

CV101_Run := AutoMode
  AND CV102_Running
  AND ChuteClear
  AND NOT PullCord;

IF CV101_Run AND NOT ZeroSpeed THEN
  ZeroSpeedTimer(IN := TRUE, PT := T#3s);
ELSE
  ZeroSpeedTimer(IN := FALSE);
END_IF;

Alm_ZeroSpeed := ZeroSpeedTimer.Q;

ST is compact, but technicians may prefer the LAD view for fault tracing.

Decision

Use LADMotor starters, conveyors, interlocks, alarms.
Use SFCLong start sequence: CV103, CV102, CV101, feeder.
Use STProduction counters, runtime totals, shift statistics.

Case Study 2: Sterilizer Batch Cycle

best default: SFC or state machine, with LAD safety/permissive rungs

SFC steps

Step 0Idle: doors unlocked only when pressure safe.
Step 1Load cage and confirm door closed/locked.
Step 2Steam fill until pressure setpoint.
Step 3Hold timer while pressure/temperature valid.
Step 4Exhaust and drain condensate.
Step 5Complete: unlock only below safe pressure.

LAD interlock version

ST01
STEP_STEAM_FILLDOOR_LOCKED/PRESS_HHSTEAM_INLET

Critical permissive is readable as a rung.

ST02
PRESS_HHRST STEAM_INLETALM_PRESS_HH

High-high pressure blocks steam inlet.

ST state machine version

CASE SterStep OF
  0: IF StartCycle AND DoorLocked THEN SterStep := 10; END_IF;
  10: IF PressurePV >= PressureSP THEN SterStep := 20; END_IF;
  20: HoldTimer(IN := TRUE, PT := RecipeHoldTime);
      IF HoldTimer.Q THEN SterStep := 30; END_IF;
  30: IF PressurePV <= SafePressure THEN SterStep := 40; END_IF;
  40: CycleComplete := TRUE;
END_CASE;

ST is good for state machines, but keep dangerous interlocks visible in LAD too.
