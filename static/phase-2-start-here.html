1. Choose Your Learning Path First

three doors into the same plant

Operator Path

Start here if you want to read the screen without worrying about Python or wiring. Focus on plant overview, station state, manual/semi-auto/auto mode, active alarms, trends, and what action the screen suggests.

  1. Open plant overview.
  2. Check which station is stopped, running, waiting, or faulted.
  3. Read alarm wording and recovery hint.
  4. Use trends to decide if the issue is new, old, or repeating.

Technician Path

Start here if you troubleshoot panels, sensors, VFDs, and networks. Focus on I/O, field feedback, communication status, trip causes, permissives, and the difference between a process fault and a network fault.

  1. Check PLC run and network health.
  2. Compare sensor/VFD status with HMI status.
  3. Trace controller/device, polling, timeout, and retry behavior.
  4. Record the fix so the next shift can recover faster.

Developer Path

Start here if you want to build data collection later. Focus on Browser -> FastAPI -> simulator state now, then Python collector -> virtual Modbus TCP -> local historian -> analytics in Phase 3.

  1. Understand the local server first.
  2. Map simulated PLC tags to registers.
  3. Poll data with Python in Phase 3.
  4. Store, trend, count, and analyze production events.

3. Industrial Communications Notes

names you will see before touching real drivers

RS-232

Point-to-point serial communication. Common on older machinery, weighing systems, barcode readers, and legacy devices. Phase 4 treats this as a focused legacy track after local analytics basics.

RS-485

Multi-drop serial wiring used by many Modbus RTU devices. Good for drives and instruments, but wiring polarity, termination, baud rate, parity, and address conflicts matter.

Ethernet

The usual plant network base for modern PLCs, HMIs, SCADA servers, engineering laptops, cameras, historians, and edge gateways.

Modbus RTU/TCP

Register-based data exchange. Modbus RTU usually runs on serial links. Modbus TCP runs over Ethernet and is the first Phase 3 hands-on protocol.

OPC UA

Structured industrial tag model for SCADA, historian, and enterprise clients. Better semantics than raw registers, but learners should understand tags/registers first.

MQTT / Sparkplug

Publish/subscribe messaging for IIoT. Sparkplug adds industrial state awareness, tag discovery, and birth/death messages on top of MQTT.

4. Computer Network And Locally Hosted Server

why the browser can see the simulator

localhost and 127.0.0.1

The browser and FastAPI run on the same computer. This is the safe default for learning because another laptop cannot control the HMI just by being nearby.

LAN IP

A LAN IP lets another device on the same network reach the server if the app binds to that address and the firewall allows the port. Treat this as a lesson, not the default.

Why not public HMI controls?

Even a simulator can teach bad habits. HMI write commands should not be exposed to unknown networks without authentication, authorization, logging, and clear safety boundaries.

Current local data flow

Browser HMI
  fetches /api/state
  sends /api/inputs/{name} or /api/commands/{command}
FastAPI local server at 127.0.0.1:8733
  reads and updates the Python PLC simulator
PLC simulator
  runs the scan cycle and returns inputs, outputs, timers, alarms, and event log

6. HMI Design Challenges Engineers Face

good screens reduce panic during faults
Bad designWhy it hurtsBetter Phase 2 teaching pattern
Too much informationOperator cannot find the fault quickly.Overview first, station details second, maintenance details third.
Bad alarm wording"Fault 43" does not teach cause or response.Use source, condition, likely cause, and safe next action.
Hidden permissivesMachine will not start but nobody knows what is missing.Show missing ready bits and interlocks near the command.
No trend/historyEvery fault feels new.Use trends and event logs so repeated problems become visible.
Weak mode visibilityManual, semi-auto, and auto ownership becomes confusing.Show who owns the command and which actions are blocked.
No role separationOperator screens become crowded with engineer-only data.Separate operator, technician, and developer views.

8. Tiny Glossary For Newcomers

words that stop being scary after one sentence
HMIHuman-machine interface: the operator screen for one machine or station.
SCADASupervisory control and data acquisition: plant-wide monitoring, alarms, trends, and sometimes supervisory commands.
HistorianDatabase-style system that stores time-stamped process values and events.
TagNamed process value such as `STER_TEMP`, `PRESS_CURRENT`, or `CPO_TANK_LEVEL`.
RegisterNumbered data location often used by protocols such as Modbus TCP.
GatewayDevice or software that bridges one system/protocol to another.
EdgeComputer near the machine that collects, filters, analyzes, or forwards plant data.
