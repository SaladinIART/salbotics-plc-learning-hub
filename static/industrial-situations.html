Different PLC brands, same ideas

Situation 1: PLC Brand Reality · Omron and Siemens are both common, but the habits differ

Omron and Siemens are two common PLC makers. The ideas are the same, but their software and wiring habits differ.

Like: Android and iPhone: both make calls, but the menus differ.

Show technical detailsHide technical details

Technical details are in English.

Omron Japan ecosystem example

Omron is common around compact machines, sensors, motion, safety, and Sysmac-style machine automation. A beginner may see CP-series style PLCs on simpler machines and NX/NJ/NX102 style controllers on modern networked machines.

Software habitThink in symbols, I/O maps, device variables, and controller tags depending on generation.
Cabinet clueOmron PLC, Omron sensors, compact remote I/O, servo or inverter devices.
Diagnostic habitCheck controller status, I/O unit health, network node status, then field device wiring.
Siemens Germany ecosystem example

Siemens is common in larger factory lines, panels using SIMATIC controllers, TIA Portal projects, PROFINET networks, distributed I/O, drives, HMI panels, and strong diagnostic tooling.

Software habitThink in device configuration, tags, blocks, networks, data blocks, and diagnostics buffers.
Cabinet clueS7-1200 or S7-1500 CPU, ET200 remote I/O, PROFINET switches, SINAMICS drive family.
Diagnostic habitCheck online device view, module diagnostics, network names/IP addresses, then field wiring.

Beginner concept: brand matters because the software, addressing language, cable, and diagnostic workflow change. The control idea stays the same: inputs are read, logic is solved, outputs are written, and faults must be handled safely.

Who asks and who answers on a network

Situation 3: Master / Device Roles · learn modern terms, but understand old manuals

In a network, one device asks and the others answer. Older manuals say master and slave; newer ones say controller and device.

Like: A teacher asking questions and students answering.

Show technical detailsHide technical details

Technical details are in English.

Words you will see

  1. Controller or scanner is the newer wording for the device that asks for data or commands another device.
  2. Device or adapter is the newer wording for the unit being commanded or read.
  3. Master and slave still appear in older manuals, especially RS-232, RS-485, and Modbus documents.
  4. Mixed Omron and Siemens lines do not have a permanent brand winner. The architecture decides which PLC coordinates the cell.

Example topologies

PLC controller run, speed, reset VFD device ready, running, fault Motor
PLC controller fieldbus scan Remote I/O device wired points Sensors
Line controller handshake Omron machine PLC handshake Siemens machine PLC

Each machine PLC should keep local interlocks and safety behavior. A line controller may coordinate recipes, permissives, production counts, and start/stop sequencing.

Example: a 4-20mA pressure transmitter may represent 0-10 bar. The PLC should show pressure in bar, not just raw counts.

Analog troubleshooting clues

Always zeroBroken loop, no sensor power, wrong input type, open common, or raw scaling set wrong.
Always maximumShort, wrong voltage/current mode, saturated transmitter, or bad scaling limits.
Jumpy valueNoise, poor shielding, bad ground, loose terminal, unstable process, or no filtering.
Slow valueSensor damping, PLC filter, HMI trend delay, or real process lag.

Controlling how fast a motor turns

Situation 5: VFD / PWM Motor Control · the PLC commands speed; the drive creates motor power

A motor drive (VFD) controls how fast a motor turns. The PLC says run and how fast; the drive does the heavy power work.

Like: You press the pedal; the engine does the work.

Show technical detailsHide technical details

Technical details are in English.

What the PLC usually does

  1. Sends a RUN command after guards, E-stop chain, overloads, and permissives are healthy.
  2. Sends direction if the machine allows forward and reverse.
  3. Sends a speed reference by analog output, network command, or preset speed bits.
  4. Reads READY, RUNNING, AT_SPEED, and FAULT feedback.
  5. Logs a drive fault and requires a correct reset sequence.

A VFD often uses PWM internally to drive the motor. The beginner should not think the PLC directly makes the motor PWM waveform.

Two sensor wiring types

Situation 6: NPN / PNP Sensor Troubleshooting · sourcing and sinking mistakes are common cabinet faults

Sensors come in two wiring types that are easy to mix up. A wrong match is a very common reason a sensor seems dead.

Like: A plug that fits but is wired the wrong way round.

Show technical detailsHide technical details

Technical details are in English.

PNP sensor

Brown +24V Blue 0V Black signal sources +24V to PLC input

PNP is often described as sourcing. When the sensor turns on, the input sees positive voltage. Many modern DC input modules are wired this way.

NPN sensor

Brown +24V Blue 0V Black signal sinks to 0V from PLC input

NPN is often described as sinking. When the sensor turns on, it pulls the input toward 0V. It only works correctly if the PLC input common is wired for that style.

Meter checklist

  1. Find the PLC input common terminal and confirm whether it is tied to 0V or +24V.
  2. Measure sensor supply between brown and blue before blaming logic.
  3. Measure black signal wire to 0V with sensor off and on.
  4. Compare the meter reading with the PLC input LED and the HMI input bit.
  5. Check if the sensor is 2-wire or 3-wire, AC or DC, NPN or PNP.

Symptoms and likely causes

LED on sensor, PLC input offWrong input common, broken signal wire, wrong NPN/PNP type, or failed input channel.
PLC input always onShorted signal wire, wrong common, leaking 2-wire sensor current, forced input, or bad module.
Input flickersLoose terminal, vibration, bad target alignment, noise, missing shield, or weak supply.
Works on meter, not in PLCInput filter, scan timing, wrong address, disabled module, or program using a different bit.

Machines that explain their own faults

Situation 7: Robust System Design · make the machine easier to diagnose before it fails

Good machines explain themselves when something goes wrong. Clear names, clear alarms and safe manual modes save hours of fault-finding.

Like: A car dashboard saying 'door open' instead of just beeping.

Show technical detailsHide technical details

Technical details are in English.

Interlocks

Do not energize an output unless all required permissives are true. Show the missing permissive on the HMI.

Handshakes

Use request, acknowledge, busy, done, and fault bits between machines instead of one vague start signal.

Alarms

Write alarms as operator sentences: source, condition, action. Avoid only saying "fault".

Signal naming

Use names that tell location, device, and meaning, such as CNV01_PE_ENTRY.

Isolation

Separate noisy motor wiring from signal wiring. Respect shielding, grounding, and panel layout rules.

Manual mode

Manual controls should still obey safety and machine-damage interlocks. Manual does not mean reckless.

Which PLC language to learn next

Situation 8: Future PLC Languages · ladder first, then compare other IEC styles later

Learn Ladder first, because technicians use it most. Other PLC languages are different ways to write the same rules.

Like: Learning to print before learning joined-up writing.

Show technical detailsHide technical details

Technical details are in English.

Ladder

Best first language for relay logic, permissives, interlocks, simple timers, and maintenance visibility.

FBD

Function Block Diagram is useful when signals flow through reusable blocks, especially analog processing.

ST

Structured Text is useful for math, scaling, recipes, loops, arrays, and compact logic.

SFC

Sequential Function Chart is useful for step-based machines, phases, transitions, and batch sequences.

Training order: understand the scan cycle and Ladder first. After that, ST, FBD, and SFC become different ways to express the same control problem.

Check yourself

Think of your answer, then tap the question to see it.

A sensor has power but the PLC never sees it. What is a common cause?

A wiring type mismatch: an NPN sensor on a PNP input, or the reverse.

Who actually makes a motor turn: the PLC or the drive?

The drive (VFD). The PLC only says run and how fast.

Why show missing start conditions on the screen?

So people can see at once why a machine will not start.
